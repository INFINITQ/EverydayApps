# 0011. Old .doc files open read-only through office_oxide, built to WebAssembly from source

- Status: accepted
- Date: 2026-10-29

## Context

Word 97-2003 documents (`.doc`) must open read-only, with "Save as .docx". The plan named
`office_oxide` (Rust, MIT OR Apache-2.0) to convert them in memory.

## Decision

- `apps/docs/legacy` is a ten-line wrapper crate around **office_oxide 0.1.15** (exact pin,
  Cargo.lock committed). `docToDocx(bytes)` reads the `.doc` into office_oxide's document model
  and writes that model as a `.docx` (`create_from_ir_to_writer`). It is outside the Cargo
  workspace because it only builds for `wasm32-unknown-unknown`.
- `node tools/build-doc-converter.mjs` builds it (release, `--locked`) and runs
  wasm-bindgen 0.2.129 into `apps/docs/src/legacy-wasm/`. The output is committed, because
  Windows builds of the app shouldn't need the wasm toolchain:
  - `folio_doc_legacy_bg.wasm` (1.2 MB)
    `dd7ac74921e6e2110b9812f19762e59a1a1283ca694f887ef7d808b7bbfab94b`
  - `folio_doc_legacy.js` (glue, `/* eslint-disable */` added)
    `49e3d5a133bef9db181a579d5b916c2dca1dc8204d73a530d35d47a8b5fa82ed`
- The app loads the `.wasm` from its own bundle on first use (the same reviewed same-origin
  load Folio PDF uses for PDFium) and starts it with `initSync`, so wasm-bindgen's default
  `fetch` is never used.
- A `.doc` opens in view mode with a notice: Folio never changes it, and Save as (F12)
  makes a `.docx` copy. "Edit anyway" unlocks editing. Save still goes to Save as, because
  the format can't be saved (`canSave: false`).
- Not the npm package `office-oxide-wasm`: its newest build (0.1.8) only exposes text,
  Markdown, HTML and the document model, and its `.doc` reader is the older line-based one.
  It flattens tables into tab-separated text, loses run formatting and leaks field codes
  (`TOC \o`, `INCLUDEPICTURE "https://..."`) into the text. 0.1.15 rebuilds tables and styles.

## Evidence

- Converting 20 public Apache POI `.doc` files (including a Word 6 and a Word 95 file, pictures,
  Cyrillic text, lists, headers and footers, footnotes, merged cells) took 2-200 ms each. 19
  converted to packages that pass Folio's own checks (`verifyPackage`), and the
  password-protected one was refused with "This document is password-protected".
- `apps/docs/src/legacy.test.ts` (11 tests): seven `.doc` files (six public, one generated by
  LibreOffice from Folio's fixture) convert, with their text present. The fixture keeps its
  table, and the editor opens the result and finds text in a cell. Password-protected and
  non-`.doc` input are refused.
- `apps/docs/test/ui.mjs`: a `.doc` opens read-only in the app with its text and the
  notice. Ctrl+S saves a new `.docx` containing the text, and the `.doc` itself is unchanged.
- Dependencies (all permissive, none networking): office_oxide, quick-xml, flate2,
  encoding_rs, serde/serde_json, indexmap/hashbrown, wasm-bindgen and their small helpers.

## Consequences

- Fidelity is office_oxide's. Headings, paragraphs, lists, tables, headers and footers, notes
  and pictures come through. Some inline formatting (bold or italic inside a paragraph) and
  table borders don't, and bullets can become numbers. Good for reading and for a first .docx;
  the original `.doc` is never altered.
- Upgrading office_oxide means bumping the pin, rebuilding, reviewing the diff of the generated
  glue, and recording the new checksums here (supersede this record).
- The converter's crates aren't in the main workspace, so `cargo deny` doesn't see them. They
  were checked by hand (above). `tools/license-report.mjs` lists them from
  `apps/docs/legacy/Cargo.lock`.
